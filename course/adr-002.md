# ADR 002 Аккаунты в серверном режиме Тіл Mix

**Дата решения** — 15 ноября 2026 года. **Статус** — реализовано и проверено на локальном экземпляре. Публичное размещение API ожидает согласования среды и оператора.

## Контекст

Пользователю нужны настройки профиля, перенос прогресса, обратная связь и доступ после входа. В публичном демо уже есть пользователи с локальными данными. Учебный проект ведёт один человек, бюджета и отдельного аккаунта облачного провайдера для API нет.

## Варианты

- **Сохранение в браузере.** Простая, бесплатная публикация на Pages. Можно поддержать профиль гостя и копию, но устройство не может служить центральной учётной базой.
- **Node.js и SQLite с единым источником.** Позволяет реализовать регистрационные формы и хранить прогресс с проверкой владельца. Потребуются поддержка сервера, управление резервными копиями и контроль среды.
- **Управляемый провайдер идентификации и хранилища.** Сокращает часть операций, но требует учётной записи поставщика и подтверждённых условий хранения в выбранном регионе. Откладывается до согласования пилота.

## Решение

Сервер разворачивает тот же интерфейс, что и Pages. Для аккаунтов Node.js проверяет запросы и хранит данные в SQLite. Выдаёт короткоживущие серверные сессии через cookie, сохраняет только солёный хеш пароля и хеш токена. Публичная статика сохраняет учебные сценарии, настройки гостя, перенос JSON, заметки и ссылки на уроки.

Данные гостя и аккаунта разделены. Копия добровольно объединяется с прогрессом владельца. Конкурирующее сохранение проверяется по ревизии. После выхода пользователю доступен предыдущий гостевой прогресс. Для пользователя без учётной записи электронная почта не собирается.

## Последствия

У разработчика есть работающий сервер и проверяемые сценарии без покупки хостинга. Перед приглашением реальных участников предстоит утвердить оператора и расположение базы, выполнить проверку копии, продумать восстановление доступа и ограничение нагрузки.
