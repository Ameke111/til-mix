# ЛЗ 13. ИИ-ассистент для статуса проекта

**Тіл Mix, неделя 13 · 30 ноября – 6 декабря 2026.** Прогоны сделаны досрочно по двум коротким итерациям от 15 ноября из [ЛЗ 9](lab-09.md). Разработка, проверка качества и публикация статуса принадлежат одному исполнителю. Отчёт готовится для преподавателя или спонсора пилота.

## 1. Рабочий процесс

Каждый понедельник собираются завершённые за предыдущую календарную неделю задачи GitHub. Срез строится по времени закрытия в UTC+5, понедельник включён, следующий понедельник исключён. Python проверяет тип записи и причину закрытия, отбрасывает PR, дубликаты и снятые задачи, вычисляет количество, среднее и P85. P85 — ближайший ранг. Отрезок от создания до закрытия совпадает с временем активной проверки для S1/S2 по их протоколу. В обычной неделе показатель отражает время жизни задачи, если отдельный старт In Progress отсутствует.

Модель получает только агрегаты и до 40 номеров задач. Ссылки, исходные отметки времени и проверяемые показатели формирует код. Модель отдельно выдаёт черновик резюме и следующего шага. Автор сверяет его с таблицей, исправляет и при необходимости передаёт преподавателю. Автоматической отправки нет.

| Этап | Вход и выход | Критерий |
|---|---|---|
| Сбор | GitHub REST Issues в публичном репозитории, включая пагинацию | При ошибке API или неполном обходе запуск завершится с ошибкой вместо частичного отчёта |
| Расчёт | Даты и ID → Markdown и JSON с фактами | Расчёты можно повторить по журналу задач независимо от модели |
| Генерация | Факты → Qwen2.5-0.5B-Instruct Q4_K_M, llama.cpp b12521 на loopback | Текст отдельно от проверенных фактов, человек утверждает следующий шаг |
| Хранение | Артефакт GitHub Actions на 14 дней | Рабочий процесс читает issues, не коммитит отчёт и не публикует его в трекере |

### Экономия времени

Время GitHub + модель составило 3,46 с для S1 и 2,57 с для S2. Один оператор Codex отдельно сверил две подготовленные сводки с известным снимком за **6 с** (18:59:34–18:59:40 UTC). Затем вручную оформил два коротких статуса по тому же знакомому снимку за **4 с** (18:59:40–18:59:44 UTC). Получилось 6,03 + 6 = **12,03 с** с моделью до правки и **4 с** для короткого статуса вручную. В этой паре прогонов чистая экономия **−8,03 с**, время внесения правки увеличило бы разницу.

Это замер работы агента на прогретых данных, с точностью до секунды и без старта модели. Он не оценивает скорость студента. На двух малых циклах полезнее расчёт Python и ручной следующий шаг. Следующее сравнение возможно после двух полных недель с независимым замером сборки одинаковых отчётов.

## 3. Инструкция для одного исполнителя

1. Скачать модель и проверить её контрольную сумму по [ЛЗ 12](lab-12.md). Запустить тамошнюю команду `llama-server` с псевдонимом `qwen-pm`. Сервер слушает только `127.0.0.1:8012`.
2. Из корня проекта выполнить команды ниже. Для публичного GitHub API локально токен необязателен. При ограничении API использовать только свой токен с чтением в переменной окружения `GH_TOKEN`.
3. Открыть Markdown и JSON. Сверить ссылки, период, поля и следующий шаг. Помечать рекомендации и прогнозы. Сохранить версию отчёта, которую передаёшь преподавателю.
4. На GitHub открыть [рабочий процесс](../.github/workflows/pm-status.yml). Расписание — понедельник 09:17 UTC+5. Ручной запуск находится в Actions → Draft weekly PM status → Run workflow. Отчёт скачать из Artifacts. Задержка запуска GitHub не означает пустую выборку.

```powershell
python course/pm-status.py --issues 23 24 --label S1 --out .til-data/pm-status
python course/pm-status.py --issues 25 26 --label S2 --out .til-data/pm-status
python course/pm-status.py --out .til-data/pm-status
```

**Запрещённые данные.** Пароли, токены, cookie, контакты, реальные ответы и история ученика, обращения, приватные issues, тела карточек, вложения, содержимое SQLite и резервных копий. Секрет GitHub передаётся только запросам GitHub API, процесс модели запускается без него. Текст запроса берётся из [шаблона](pm-status-prompt.txt), обработка происходит локально на машине или внутри одного раннера. [Скрипт](pm-status.py)
