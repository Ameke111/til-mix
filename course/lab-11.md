# ЛЗ 11. План тестирования, UAT и разбор инцидента

**Тіл Mix, неделя 11 · 16–22 ноября 2026.** Внутренний прогон прошёл 18 ноября. Проект индивидуальный. Студент отвечает за стенд, тесты, триаж и выпуск. Внешнюю приёмку проводят участники другой команды в роли заказчика. Их согласование и подпись остаются открытыми.

## 1. Стратегия качества

| Уровень | Объём и среда | Критерий выхода |
|---|---|---|
| Модульный | `node --test`, ветви уроков, варианты перевода, карточки, XP, старый прогресс, очередь ошибок | Все тесты зелёные. Старый экспорт открывается, исправленная фраза сохраняет состояние при слиянии |
| Интеграционный | Node.js 24, локальный HTTP и SQLite. Регистрация, вход, выход, конфликт версии, аккаунты и роли | Чужой аккаунт не читает и не меняет данные. Устаревшая версия отклоняется. Роль владельца можно отозвать |
| Сквозной | Chromium на `127.0.0.1:4318`, сценарии ниже. Отдельный smoke публичной гостевой версии после публикации | Базовые учебные сценарии работают. Фокус виден, основные действия доступны с клавиатуры и на узком экране |
| Нагрузочный smoke | k6, локальный `GET /api/health`. Три виртуальных пользователя, восемь секунд | 0% неудачных запросов, p95 до 250 мс. Регистрация, отправка обращений и хранилище требуют отдельной нагрузки |
| Мониторинг и поставка | Uptime Kuma в Docker, HTTP каждые 60 секунд. CI проверяет lint, тесты, сборку, npm audit и Trivy | Демо-API отвечает 200. Прежний артефакт остаётся опубликован при блокировке CI |

Данные внутреннего прогона — гостевой профиль, фразы публичных уроков, синтетические обращения демо и временные SQLite-базы. Для внешней сессии нужен чистый профиль. Зафиксировать браузер и сборку. Озвучка требует системного голоса `kk-KZ`. Естественность фраз оценивает преподаватель по четырём историям пилота из [плана](semester-plan.md).

**Внутренний итог.** Девять сценариев пройдены. Сборка, lint и 43 автоматических теста прошли, npm audit сообщил о 0 уязвимостей. Два последовательных heartbeat проверили демо-`/api/health` с результатом 200 OK. k6 получил 8 576 корректных ответов, 0 отказов и p95 4,53 мс. Такой срез не даёт оценки месячного SLO.

**Внешний протокол.** Один участник другой команды проходит UAT-01–08 за 20 минут, второй по возможности наблюдает. Следующие пять минут отводятся UAT-09. Для каждого сценария записать ID, сборку, устройство, шаги, фактический результат, статус и отметку заказчика. Для вложений использовать синтетические данные. Проведение, результат и подпись заказчика остаются открытыми.

**Триаж.** P0 — потеря прогресса, недоступность диалога или доступ к чужим данным. Выпуск остановить. P1 — воспроизводимый сбой поиска, упражнений, клавиатуры или очереди владельца. Назначить срок и повторить сценарий. P2 — оформление и тексты без блокировки. Добавить в очередь. В проведённых сценариях новых P0/P1 не зарегистрировано. Корректирующие действия записаны в [бэклоге ЛЗ 11](lab-11-backlog.md).

## 4. Runbook. Аудит зависимостей остановил Pages

1. Открыть CI, записать ветку, SHA, время, этап и идентификатор предупреждения. Уточнить граф через `npm explain <package>` и `npm audit`.
2. Открыть публичный адрес. Если предыдущая версия доступна, записать SHA последней успешной выкладки и отложить выпуск до исправления. Если публичная страница недоступна, открыть P0 и проверить статус GitHub Pages.
3. Проверить официальное исправление и совместимость. Обновить версию с lock-файлом в отдельной ветке. Если исправленной версии пока нет, оценить замену зависимости, прогнать регрессию учебных сценариев.
4. Выполнить `npm ci`, lint, тесты, сборку и аудит. Проверить статусы PR и выпускать после зелёного CI. Если публикация уже сломала базовый сценарий, открыть revert PR для исправления.
5. После выпуска открыть гостевую страницу, пройти UAT-01 и один диалог. Для локального демо проверить также `GET /api/health`. Записать время восстановления и результаты в задачу.

### Воспроизведение мониторинга

```powershell
npm run build
$env:TIL_DEMO_PORT='4318'
node demo.js
```

В другом терминале запустить отдельный Uptime Kuma на loopback.

```powershell
docker run -d --name til-mix-uat-kuma -p 127.0.0.1:3031:3001 --mount type=volume,source=til-mix-uat-kuma,target=/app/data louislam/uptime-kuma:2
```

Открыть `http://127.0.0.1:3031/`, выбрать SQLite. Создать монитор HTTP(s) на `http://host.docker.internal:4318/api/health` с интервалом 60 секунд. Для существующего контейнера использовать `docker start til-mix-uat-kuma`.

Для запуска k6 с теми же порогами, пока стенд доступен, выполнить `Get-Content -Raw course/lab-11-smoke.js | docker run --rm -i grafana/k6:latest run --quiet -` в PowerShell.
