## 1 Политика доски

| Статус | Правило входа и выхода |
|---|---|
| Backlog | Идея, риск или обязательство курса. Для уточнения добавить сценарий, приоритет, нужные подтверждения |
| Ready | Одно наблюдаемое условие приёмки, владелец Ameke111, оценка, известные зависимости и данные проверки |
| In progress | Исполнитель взял одну задачу и может сразу её проверить. Настроенный лимит **1**. В измеряемой выборке issue создавалось при активном старте |
| In review | Изменение готово, но требуется внешняя вычитка, UAT или уточнение. В карточке фиксируется дата ответа. Активная работа в это время относится к другой независимой задаче |
| Done | Сохранена проверяемая отметка: результат теста, закрытый issue, ссылка на релиз или протокол. Документы и язык отмечаются по собственным критериям |

**DoR.** Есть входной сценарий, критерий, владелец, ограниченная задача и возможность проверки. **DoD.** Путь пройден, ожидаемый результат наблюдался, в трекере указан результат. Для изменений кода также проходят линтер, тесты и сборка. Для данных пилота применяются только разрешённые записи.

Класс стандартный — одна история за раз. Блокирующая ошибка может стать первой в очереди, при этом незавершённая работа возвращается в Ready с причиной и текущим состоянием.

## 4 Метрики

Cycle time — от фактического начала проверки до закрытия. Эти события совпадают с `created_at` и `closed_at` по принятой процедуре. Throughput — количество закрытых issue внутри итерации. P85 по ближайшему рангу при двух наблюдениях соответствует большему значению. CFD построена по последовательности четырёх карточек, плановые карточки в начале находятся в очереди, затем переходят в проверку и Done.

| Итерация | План / факт | Среднее, мин | P85, мин | Максимальный WIP по событиям |
|---|---:|---:|---:|---:|
| S1 | 2 / 2 | 1,67 | 1,82 | 1 |
| S2 | 2 / 2 | 0,67 | 0,75 | 1 |

Среднее сократилось примерно на 60%, но выборка включает разные проверки и всего по две задачи. Результат совместим с пользой готовых данных, отдельный причинный эффект не измерялся. CFD показывает последовательную работу без накопления нескольких активных задач. Для сравнения недельных спринтов потребуются ещё два полных цикла с записью старта разработки, входа на проверку и завершения. [Следующая контрольная точка](semester-plan.md)

```bash
python course/delivery-metrics.py
```

Флаг `--refresh` собирает новый снимок общедоступного API. Текущие цифры привязаны к сохранённым исходным событиям и воспроизводятся без доступа к сети. Codex помог структурировать отчёт. Времена выгружены из GitHub.
